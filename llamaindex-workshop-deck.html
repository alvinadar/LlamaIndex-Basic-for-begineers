Read this slide twice

What you will assume

“Node = a step in my program.” Every graph framework you have ever seen uses the word that way, so your brain will supply it for free.

What it actually means

A Node is a chunk of your document. A piece of text with an embedding and some metadata. Nothing to do with program flow.

Node = piece of text. Step = piece of code. Get this wrong now and every error message for the next hour will read like nonsense. source_nodes, node_parser, NodeWithScore — all of them mean text.

Take the controls back

from llama_index.core.node_parser import SentenceSplitter

Settings.node_parser = SentenceSplitter(chunk_size=500, chunk_overlap=50)
retriever = index.as_retriever(similarity_top_k=3)

# show your work - the habit survives the framework
response = query_engine.query("Seal doesn't match the ASN. What do I do?")
for node in response.source_nodes:
    print(round(node.score, 3), node.text[:120])

Try it: chunk_size=100, then 2000. Small chunks are specific, big chunks are complete. There is no correct answer — which is exactly why the framework let you change it.

8

What would you have done?

Reworded it and searched again. Obvious, human, and impossible in one function call — because a query engine only moves forward.

A query engine

retrieve → answer → done. Every question takes the same road at the same speed, whether the search worked or not. No looking back.

A Workflow

retrieve → check → and now there is a fork: answer it, or go back and search differently. Loops are legal.

Five lines are a demo. The loop is the product. Everything for the next 45 minutes is building that one arrow backwards.

9

Three words, then you know it

Event

A message with data in it — and the thing that decides what runs next.

Step

An async method. Accepts one event type, returns another. One job each.

Context

The shared store that survives across steps and across loops.

Then the sentence that makes the whole framework click: there are no edges. You never wire steps together. A step returns an event, and whichever step accepts that event type runs next. The type hints are the wiring.

10

Define the events first

from llama_index.core.workflow import (
    Workflow, Context, Event, StartEvent, StopEvent, step,
)

class RetrieveEvent(Event):
    question: str        # the question being searched RIGHT NOW

class GradeEvent(Event):
    chunks: list[str]

class RewriteEvent(Event):
    pass                 # carries nothing. it only means "try again".

class GenerateEvent(Event):
    chunks: list[str]

Design the events and you have designed the program. Sketch these four on paper before writing a single step — the steps almost write themselves afterwards.

11

The first two steps

class SelfCorrectingRAG(Workflow):

    @step
    async def begin(self, ctx: Context, ev: StartEvent) -> RetrieveEvent:
        await ctx.store.set("original", ev.question)   # never changes
        await ctx.store.set("attempts", 0)             # the loop guard
        return RetrieveEvent(question=ev.question)

    @step
    async def retrieve(self, ctx: Context, ev: RetrieveEvent) -> GradeEvent:
        attempts = await ctx.store.get("attempts")
        await ctx.store.set("attempts", attempts + 1)
        await ctx.store.set("question", ev.question)
        nodes = await retriever.aretrieve(ev.question)
        return GradeEvent(chunks=[n.text for n in nodes])

Rule 1 — anything that must survive the loop goes in Context, not in an event. Events are for this hop. Context is for the whole run. Rule 2 — ctx.store is async. Every get and set is awaited.

12

The grader: the return type is the fork

    @step
    async def grade(
        self, ctx: Context, ev: GradeEvent
    ) -> GenerateEvent | RewriteEvent:
        original = await ctx.store.get("original")
        verdict = str(await Settings.llm.acomplete(
            f"""EXTRACTS:
{chunks_text}

QUESTION: {original}

Can the question be answered using ONLY these extracts?
Reply with one word: YES or NO.""")).strip().upper()

        if verdict.startswith("YES"):
            return GenerateEvent(chunks=ev.chunks)
        return RewriteEvent()

No router function, no mapping dict, no edges. The union in the return annotation is what tells the workflow this step has two exits — and if/return is what picks one.

13

One line makes it a loop

    @step
    async def rewrite(self, ctx: Context, ev: RewriteEvent) -> RetrieveEvent:
        original = await ctx.store.get("original")
        last     = await ctx.store.get("question")
        better = str(await Settings.llm.acomplete(
            f"""ORIGINAL: {original}
LAST SEARCH: {last}
Rewrite it using the vocabulary a formal SOP document would use.""")).strip()
        return RetrieveEvent(question=better)      # <-- the loop

The timeout is a safety net, not a design. Every loop needs a counter in Context and a ceiling in a step. The timeout catches a runaway after you have paid for it.

16

The guard and the honest exit

    @step
    async def grade(
        self, ctx: Context, ev: GradeEvent
    ) -> GenerateEvent | RewriteEvent | StopEvent:     # one more exit
        ...
        if verdict.startswith("YES"):
            return GenerateEvent(chunks=ev.chunks)

        attempts = await ctx.store.get("attempts")
        if attempts >= 3:                             # the ceiling
            return StopEvent(result=
                "Not in the operations manual - escalate to the duty supervisor.")
        return RewriteEvent()

Last week's refusal was a shrug. This one is earned — three different searches were tried before it said no, and the event stream can prove it.

18

Six things that will bite you

  • “Node” means chunk, not step. Half the confusion in this room today traces back to this one word.
  • Forgetting await on ctx.store → you store a coroutine instead of a value, and the error appears one step later.
  • No loop guard → the timeout eventually fires, after you have paid for every lap.
  • Two steps accepting the same event type → both run. Sometimes intended, usually a bug.
  • An event nobody accepts → validation fails before anything runs. Read the message; it names the orphan.
  • Loop state kept in an event instead of Context → it resets every lap and your counter never grows.

Homework — add a third road

Scenario: some questions are too vague to search at all. “help”, “problem lah”, “what about the thing”. Rewriting them is guessing. Asking back is correct.

Part A — build (60%)

A3 Make sure it does not burn an attempt
A4 Put your draw_all_possible_flows output in the README

Part B — break (40%)

B1 One question that only works because of the rewrite loop — paste both laps from the event stream
B2 One question where the grader is wrong — says YES on chunks that don't answer it. Explain why
B3 Your ceiling, and one sentence on why that number

Submit: the script plus a short README. B2 is the hardest mark on the sheet — a grader you cannot fool is not a grader you have tested.

Take this home

  1. Five lines are a demo; the loop is the product. The convenience layer is worth using precisely because you know what sits under it.
  2. In LlamaIndex, types are the wiring. No arrows to draw — say what a step accepts and what it returns, and the shape of the program follows.
  3. “I couldn't find it” is worth more when it's earned. Three genuine attempts, and an event stream that can show you all three.
